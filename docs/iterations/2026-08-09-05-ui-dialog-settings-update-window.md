# 模态层、设置选择项与更新窗口

日期：2026-08-09

## 状态

已验收。

## 范围

- 统一修正窗口内模态对话框层级，使遮罩和内容覆盖包括 Windows 自绘拖动区在内的完整 WebView；macOS 原生交通灯仍保持平台原生行为。
- 重构设置页面布尔选择项：整行均可点击，整行使用指针光标与明确 hover 背景，复选框底色和选中态在浅色/深色主题下均有足够区分。
- 检测到新版本时打开单例独立更新窗口，不再把可用更新确认嵌在设置页；启动自动检查与手动检查复用同一窗口。
- 将 Release 提供的更新说明视为不可信 Markdown，只渲染受限的排版、列表、代码和链接结构，不使用原始 HTML；外链继续通过受控系统打开边界。
- 补齐 `zh-CN` / `en-US` 文案、最小窗口 Capability、窗口标题/状态约定和针对性测试。

## 非目标

- 不修改更新清单格式、Geo 路由、签名校验、安装流程或更新信任根。
- 不引入通用 Markdown 编辑器、HTML 渲染器或任意网络/文件/Shell 权限。
- 不修改应用版本，不提交、推送、创建 tag 或发布。

## 验证门禁

- 共享 Modal 的遮罩和内容层级高于自绘标题栏，关闭、焦点与键盘行为保持可用。
- 设置页所有布尔选择项的可点击范围覆盖标题与说明区域，并有可辨识的 hover、focus-visible、选中和禁用状态。
- 更新可用时只复用一个更新窗口；窗口关闭、重新检测、下载安装和安装失败路径可恢复。
- Markdown 渲染拒绝原始 HTML、脚本和危险协议，链接只允许受控的 `http` / `https` 外部打开。
- 执行针对性测试、`pnpm test`、`pnpm build`、必要的 Rust 检查及 `git diff --check`；不运行 Tauri bundle。

## 实施结果

- 共享 Dialog 的遮罩与内容层级提高到自绘标题栏之上，Windows 下可覆盖完整 WebView；原有 Radix 焦点管理和键盘关闭行为不变。
- 设置页布尔选择项统一为标题、说明和复选框组成的整行交互区域，增加语义化底色、hover/focus 反馈，并用 `aria-labelledby` / `aria-describedby` 保持清晰的无障碍名称与说明。
- 更新检查结果由 Rust 暂存；检测到新版本时创建或复用单例 `update` 窗口。设置页手动检查和启动自动检查复用相同入口，更新窗口仍调用原有签名下载安装命令。
- 更新说明使用 `react-markdown` 解析，只允许基础文本、标题、列表、引用、代码与链接；禁用原始 HTML、图片和危险协议，允许的 HTTP(S) 链接仍由 Rust 外链边界复验后交给系统浏览器。
- 新增独立最小 `update` Capability、双语窗口标题和稳定错误文案；发布说明在 Rust 侧限制为 64 KiB，避免异常清单无界占用界面内存。

## 手动验收

- Windows：分别从主窗口关闭询问、设置页确认框等入口检查遮罩是否覆盖顶部拖动区，键盘焦点及 Esc/关闭按钮是否正常。
- 设置页：检查浅色/深色主题下整行 hover、点击标题或说明切换、键盘 focus-visible 与禁用态。
- 使用包含标题、列表、代码、普通 HTTPS 链接及原始 HTML 的测试 Release notes 检查独立更新窗口；确认窗口只创建一个、危险内容不渲染、链接由系统浏览器打开、下载安装仍需显式点击。

## 验收反馈修正

- 首轮验收发现选择项 hover 对比度不足，且交互区域只覆盖卡片内层内容宽度，没有横向贯穿所属容器。
- hover 改用主题语义 `accent` 底色；选择行横向抵消设置卡片 padding，使点击与 hover 区域从容器左侧贯穿到右侧。关于页更新选项和写信页默认签名选项同步遵循该规则。
- 修正后针对性测试 10 项、完整前端测试 129 项与生产构建均通过；构建产物已确认包含 `hover:bg-accent` 和完整行宽度规则。
