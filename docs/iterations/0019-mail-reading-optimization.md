# 第十九阶段：邮件阅读优化

## 状态

已验收。

验收日期：2026-07-27。

## 目标

在不放宽既有脚本、表单、同源、顶层导航、任意文件与任意网络权限的前提下，重构邮件阅读页的信息层级与附件体验，补齐标准 CID 与受限内联 data 图片兼容，并改善长列表分页和批量新邮件通知的呈现。

## 已确认范围

### 阅读页结构

- 邮件标题置于阅读页最上方，并保持可选中。
- 标题下方使用浅色、细边框、圆角的单一内容容器，依次包含：
  1. 基本信息区：发件人、收件人、抄送/密送（存在时）、附件概况；
  2. 右侧操作区：时间、星标、回复、回复全部、转发、归档、移动、复制、删除及更多操作；
  3. 正文区；
  4. 附件区。
- 不实现参考图中的智能回信。
- 发件人、收件人、邮件标题和正文继续允许用户选择复制；展示性控件继续不可选。
- 正文仍由 Rust 清洗并在现有 sandbox iframe 中渲染，不因页面结构调整改变安全边界。

### 附件卡片

- 单个附件改为固定宽度、可响应收缩的经典左右结构：
  - 左侧显示按常见 MIME 类型归类的文件图标；
  - 右侧上方显示文件名，下方显示文件大小；
  - 悬浮和键盘聚焦时在卡片右侧显示“打开/下载”和“另存为”操作。
- 使用项目现有 `lucide-react` 中性文件类型图标，不新增依赖；类型无法识别时使用通用文件图标。
- 卡片本体仍可执行主操作：本地已有附件直接打开，未下载附件先下载并遵循现有“下载后自动打开”偏好。
- 附件标题、文件名和操作提供中英文生产级文案及可访问名称。

### 标准 CID 内联图片

- 按 RFC 2392 解析 `cid:`：
  - 去除 `cid:` 前缀与 Content-ID 的尖括号；
  - 对 CID URL 执行 `%hh` 解码后再与 MIME `Content-ID` 规范化匹配；
  - 匹配不依赖大小写或发信客户端对 `Content-Disposition` 的分类习惯。
- 从完整 MIME part 集合建立 Content-ID 索引，而不是只遍历解析器认定的普通附件。
- 只内联正文实际引用且成功进入安全清洗结果的 PNG、JPEG、GIF、WebP part；发件方误标为 `application/octet-stream` 时，只有解码字节的文件魔数能确认上述四种格式才兼容内联，不信任文件名；沿用单项 25 MB、单封累计 100 MB 上限。
- 只有成功内联的 part 才从附件列表排除；未引用、无法匹配、类型不支持或超过上限的 part 继续显示为附件，不静默丢失。
- 回归语料覆盖 `inline`、`attachment`、无 disposition、转义 CID、大小写差异、嵌套 `multipart/related`、阿里云式 `application/octet-stream` CID，以及未引用或文件魔数不匹配的 Content-ID。

### 受限 data 图片

- 阅读路径允许经过严格验证的 `data:image`：
  - 仅接受 PNG、JPEG、GIF、WebP；
  - 校验 media type、编码格式和解码后大小；
  - 与 CID 图片共享单项和单封累计上限；
  - 拒绝 SVG、HTML、未知类型、格式错误或超限数据。
- iframe CSP 仍保持 `default-src 'none'; img-src data:; style-src 'unsafe-inline'`，不开放脚本、同源、本地文件或额外网络能力。

### 邮件列表自动分页

- 在“设置 → 阅读”增加“滚动到底时自动加载更多邮件”开关。
- 开启时，当前文件夹或当前搜索结果接近列表底部后自动调用现有 TanStack Query `fetchNextPage`，同一页请求期间不重复触发。
- 关闭时保留现有“加载更多”按钮。
- 偏好继续作为设备级阅读偏好存储，并通过现有稳定 DTO 与事件桥同步；React 不自行持久化。
- 默认开启，用户可随时关闭并恢复手动分页按钮。

### 批量新邮件通知

- 一个同步批次产生的合格候选超过用户设置的层叠数量 `X` 时，只保留时间顺序最后的 `X` 封。
- 层叠模式一次性提交保留后的批次并统一排布，避免逐个创建、淘汰和重排造成窗口闪动。
- 覆盖模式只呈现该批次最后一封，避免同一窗口在极短时间内反复覆盖。
- 账户/文件夹开关、去重、通知时长、点击定位和最多层叠数量的现有语义不变。

### 独立窗口就绪显示

- Composer、设置、账户管理、原始邮件和通知窗口由 Rust 隐藏创建。
- React 完成懒加载和首批 Query 后显示窗口；普通窗口同时聚焦，通知窗口保持不抢焦点。
- 普通窗口 Capability 只增加自身 `show`/`setFocus`，通知只增加自身 `show`；不增加任意建窗、文件、网络或系统 opener 权限。
- Query 失败时仍显示生产级错误状态，不让窗口永久隐藏。

## 本阶段暂不实施

- 智能回信、AI 摘要或标签。
- 邮件杀毒能力或“附件安全”结论展示。
- SVG data 图片、任意 data URL、iframe 本地文件权限或新的网络权限。
- 会话聚合、统一收件箱、联系人或其他未排期功能。

## 手动验收

1. 分别打开纯文本、普通 HTML、长正文、无附件和多附件邮件，确认标题、信息、操作、正文和附件都位于单一浅边框容器内，滚动与选择复制正常。
2. 检查 PDF、图片、压缩包、Office 类和未知类型附件的图标、固定宽度、长文件名截断、悬浮/键盘操作、下载后打开与另存为。
3. 使用包含 `Content-ID` 的真实 Foxmail/Outlook/阿里云等邮件，确认正文 CID 图片离线显示且不重复出现在附件区；其中阿里云式 `application/octet-stream` PNG 应通过文件魔数识别，未引用或伪装成图片的 CID part 仍显示为附件。
4. 使用 PNG/JPEG/GIF/WebP 的合法 `data:image` 邮件，确认图片显示；SVG、错误编码和超限 data 图片被安全拒绝。
5. 开启自动分页后滚动到邮件列表底部，确认只加载一次下一页并能继续滚动；关闭后确认恢复手动按钮；当前文件夹和搜索结果均验证。
6. 将通知最多层叠数量设为较小值，让一次同步产生更多新邮件，确认只出现最后 `X` 个窗口且不高速闪动；覆盖模式只显示最后一封。
7. Windows 10 22H2+ 完成浅色/深色、主题色、键盘与窗口实机验收；macOS 12+ 只有实际执行后才记录通过。

## 实施结果

- 阅读页已经重构为顶部标题与单一浅边框内容容器，基本信息、操作、正文和附件层级明确。
- 附件卡片已按常见文件类型使用克制的彩色 Lucide 图标，并保留打开/下载、另存为和键盘可访问性。
- CID 按 RFC 2392 规范化并扫描完整 MIME part；受限 raster `data:image` 已通过类型、编码、文件魔数和大小预算门禁。
- 迁移 0021 会从本地原始 EML 离线重建标准 CID/data 图片正文；针对实机已应用 0021 后发现的阿里云 `application/octet-stream` CID 兼容，迁移 0022 再次失效旧安全 HTML 缓存并升级至数据格式 22，重建时事务清理成功内联的重复附件投影。
- 自动分页偏好、通知批次裁剪及独立窗口内容就绪后显示均已实现。
- 自动验证已通过：前端 33 个测试文件共 95 项、Rust 138 项、前端生产构建、Rust fmt 和 Clippy。
