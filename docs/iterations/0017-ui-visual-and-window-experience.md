# 第十七阶段：UI 视觉与窗口体验优化

## 状态

已验收。

开始日期：2026-07-26。

验收日期：2026-07-26。

## 目标

本阶段不增加新的邮件协议、同步入口或邮件内容能力，只收敛已经实现界面的滚动、窗口呈现和若干已发现的交互细节：

1. 建立不占用主体宽度的全局统一自绘滚动条规则，消除滚动条出现/消失引起的内容宽度变化；仅文件夹列表按产品要求自动隐藏。
2. 把账户管理与原始邮件查看从主窗口弹层迁移为独立 Tauri 窗口。
3. 精简同步进度文案，并修正设置加载态、账户身份排版、通知定位已读和阅读正文留白。

## 实施范围

### 1. 统一覆盖式滚动条

- 应用滚动容器隐藏 WebView 原生滚动条，统一通过 `OverlayScrollArea` 在组件既有 padding/margin 内覆盖自绘滑块；滑块不占用主体宽度，也不使用 `scrollbar-gutter`。
- 默认只要内容可滚动，自绘滑块就始终可见且可拖动；文件夹列表是唯一启用 `autoHide` 的滚动区，在指针悬停或键盘焦点进入时显示。
- 邮件列表为滚动滑块保留更宽且位于列表容器内部的鼠标命中区，避免与右侧分栏拖拽条竞争。
- 设置、初始向导、账户管理、菜单、通知文件夹列表、纯文本正文、Composer 和其他既有纵向滚动容器遵守同一规则。

### 2. 独立账户管理与原始邮件窗口

- 账户菜单和无账户空状态通过稳定 API 请求 Rust 创建或聚焦单例账户管理窗口，不再在主窗口渲染账户管理弹层。
- 原始邮件通过单例独立窗口读取；重复查看另一封邮件时复用窗口并用窄事件切换账户/邮件目标，不把原始 EML 推入事件。
- 两类窗口拥有独立 Capability，只开放稳定 Command、必要窗口控制和事件能力；React 不获得任意建窗、文件系统、Shell、数据库或邮件服务器权限。
- 两类普通窗口沿用首次居中、后续恢复尺寸与位置、Windows 自绘标题栏和 macOS 原生交通灯规则。

### 3. 视觉与交互修正

- 同步进度只在邮件摘要阶段显示当前文件夹内 `已同步/总数`，格式为“正在同步 XXX (123/321)”；不再显示文件夹完成数/总文件夹数。
- 设置窗口的懒加载回退覆盖完整窗口，不提前露出标题栏拖拽区域或左右栏背景接缝。
- 账户身份允许名称与邮箱在可用宽度内完整换行，箭头和头像不挤占文本的最小宽度。
- 账户管理详情的自绘滚动视口为表单焦点环保留左侧安全区，并以等量负外边距维持原有内容对齐；下拉框聚焦时不再被视口边界裁切。
- 未保存外观偏好时默认使用浅色主题，不再默认跟随系统；系统、浅色、深色选项和用户已有持久化选择保持不变。
- 点击新邮件通知后，Rust 在发出定位事件前把仍然存在的目标邮件排入已读更新；定位和已读使用同一经核验账户/文件夹/邮件目标。
- HTML 与纯文本正文在阅读栏左右保留小幅宿主留白；邮件 iframe 的作者布局、安全清洗和 sandbox 权限不变。

## 非目标

- 不改变启动、定时、手动同步时机，不增加 IMAP IDLE。
- 不改变同步批量网络读取、逐封落库或 100ms 前端增量合并语义。
- 不修改 HTML 清洗、远程图片、外链、CID、附件或 Composer 安全边界。
- 不增加协议、数据库迁移、依赖、根 Cargo Workspace、业务子 crate 或前端持久化。
- 不在本阶段实现会话、托盘、系统通知中心、OAuth、POP3 或发布功能。

## 实机验收门禁

Windows 10 22H2+：

1. 逐一打开主工作区、设置、账户管理、原始邮件、Composer、初始向导及包含长列表的弹层；除文件夹列表外，所有纵向滚动条在内容可滚动时始终可见，且覆盖在既有留白内、滚动时内容宽度不跳动。
2. 文件夹列表未悬停且焦点不在列表内时隐藏滑块；指针移入或键盘焦点进入时显示并可拖动，文件夹主体宽度保持不变。
3. 在邮件列表拖动滚动滑块，确认命中区明显宽于视觉滑块，且不会误触右侧分栏拖拽。
4. 从账户菜单和无账户空状态打开账户管理；重复打开只聚焦同一窗口，账户添加、编辑、重新认证、同步间隔、文件夹映射和移除保持正常。
5. 连续查看两封邮件的原始内容；独立窗口复用并显示对应 EML，原文可选择、滚动，主阅读窗口不出现原文弹层。
6. 打开设置窗口观察首次加载，确认不会先露出上方拖拽区背景接缝。
7. 使用长发件人名和长邮箱账户，确认身份信息完整呈现；同步时只显示当前文件夹及邮件进度，不显示文件夹数量。
8. 点击未读邮件通知，主窗口定位后该邮件立即为已读；HTML 与纯文本正文左右留有适度空隙且原邮件布局不被改写。
