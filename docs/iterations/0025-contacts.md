# 第二十五阶段：联系人完整能力与初版体验

## 状态

已验收（2026-08-09；模板字段布局与全局模板的当前账户联系人候选补充修正已通过用户验收）。本文件中的全部能力属于同一个阶段，不占用第二十六及后续阶段编号。

## 阶段目标

一次完成 NextMail 的本地联系人能力：联系人按账户独立存储，收信时自动沉淀所有可观察的收发信地址；主窗口增加独立联系人模块；邮件列表优先使用联系人姓名；邮件阅读器和 Composer 中的联系人支持悬浮名片、右键复制与本地联系人选择；最后以真实数据、跨账户和 Windows/macOS 检查完成初版质量收口。

## 一、联系人数据与自动沉淀

### 产品语义

- 联系人全部保存在当前可迁移数据目录的 `content.sqlite`，不上传到邮件服务器或第三方服务。
- 每个联系人严格绑定匿名 `account_slot_id`；相同邮箱地址在不同账户中是两个互不影响的联系人。
- 同一账户内按规范化邮箱地址去重。规范化只做首尾空白清理和 ASCII 大小写折叠，不做 Gmail 点号、`+tag` 或其他服务商特例合并。
- 自动发现新联系人时优先采用同封邮件中该邮箱有效的邮件头显示名，没有显示名才取邮箱地址 `@` 之前的前缀；同账户已匹配邮箱的本地联系人一律不因后续邮件头变化而修改。
- 收取全部可选文件夹时处理本地可观察的发件与收件地址，包括 `From`、`Sender`、`Reply-To`、`To`、`Cc` 和 `Bcc`；缺失、畸形或无邮箱地址的条目安全跳过。
- 已有本地邮件执行一次幂等、可恢复的后台回填，至少覆盖当前已持久化的 `From`、`To` 和 `Cc`，使升级后联系人页不会只从新邮件开始积累。
- 联系人和邮件的关联保存在账户隔离的本地投影中，用于最近往来和批量身份解析；同一封邮件重复同步不得重复创建联系人或关联。

### 数据与架构

- 新增只增不改的 `0025` SQLx 迁移，建立联系人表、必要索引、联系人—邮件关联和回填进度；不修改已发布迁移。
- 联系人使用稳定随机 ID；同一账户槽以 `(account_slot_id, normalized_email)` 建立唯一约束。展示邮箱、联系人名称、名称来源和时间戳与规范化键分离保存。
- 邮件地址解析仍位于协议 Adapter；联系人去重、自动命名和关联规则位于 Rust 业务/存储边界，不在 React 或 IMAP Adapter 中散落 SQL。
- 单封邮件的消息投影、联系人插入和关联重建在同一短 SQLite 事务内提交；网络、MIME 解析和历史回填批次准备不持有写锁。
- 历史回填按账户和稳定游标分批执行，允许中断后继续，不阻塞首帧、账户切换或正常同步；重复运行结果保持一致。
- Repository 的联系人 CRUD、列表、搜索、详情、最近往来和批量解析接口都先由公开 `account_id` 解析到匿名账户槽，并在 SQL 中复验账户归属。
- Command 保持薄；联系人变化事件只携带公开账户 ID 与修订号，驱动 TanStack Query 精确失效，不推送联系人列表或邮件内容。
- 不覆盖持久化邮件头中的原始显示名。UI 使用独立的解析展示 DTO，使联系人姓名、邮件头名称和原始邮箱仍可区分。

## 二、独立联系人工作区

### 一级入口与工作区状态

- 在“写新邮件”按钮和“邮件文件夹”标题之间增加“联系人”按钮，视觉层级与 Inbox 等一级入口一致，折叠侧栏时保留可访问名称和图标提示。
- 主窗口引入显式 `mail | contacts` 工作区状态；联系人不是 `MailboxSummary`，也不使用虚假 mailbox ID。
- 点击联系人切换中间栏和右侧栏；点击任意真实文件夹切回邮件工作区。账户切换时保留工作区类型，但立即切换到目标账户的数据并清空无效联系人选择。
- 联系人查询、选择、搜索和缓存 key 都包含当前公开账户 ID，不提供跨账户合并视图。

### 联系人列表与详情

- 中间栏显示标题、当前账户联系人数量、手动新增按钮和按姓名/邮箱搜索框；列表稳定排序、分页，只查询本地 SQLite。
- 联系人列表的指针、悬停、行距、选中背景和左侧强调边框与收件箱邮件列表使用同一视觉设计语言。
- 列表项使用姓名首字母生成的本地占位头像，展示名称和邮箱；不生成或下载人物照片。
- 右侧详情显示姓名、邮箱和本地创建/更新时间；账户归属由当前账户侧栏上下文明确，详情提供“发送邮件”和“编辑联系人”。
- 使用联系人—邮件关系展示当前账户内最近往来；点击记录切回邮件工作区并定位对应邮箱和消息，不发起服务器搜索。
- 支持手动新增姓名与邮箱；同账户已有规范化邮箱时拒绝重复创建并给出明确错误。
- 支持修改联系人姓名；邮箱是本地身份键，创建后保持只读，避免历史邮件失去身份匹配或后续同步重新生成旧地址联系人。
- 暂不提供删除入口，避免“同步发现必须补齐”与用户删除意图产生未定义冲突。
- 提供加载、空状态、无搜索结果、后台回填、错误和重试状态，不显示阶段名、数据库或调试说明。

### 参考图边界

- 参考用户 demo 的信息层级、留白和三栏布局，不逐像素照搬未定义数据。
- 电话、部门、职位、地址、照片、标签、收藏、组织关系等没有数据来源的内容不做假数据、占位字段或隐含路线。

## 三、邮件身份解析与互动

### 姓名解析

- 展示优先级固定为：当前账户本地联系人姓名 > 邮件头或草稿已有显示名 > 邮箱地址。
- 联系人匹配只使用当前账户槽和规范化邮箱，绝不从其他账户借用姓名。
- Rust 查询层批量返回联系人 ID、解析名称和原始地址信息；邮件列表不得逐行调用联系人 Command 或形成 SQLite N+1 查询。
- 联系人名称修改后，通过账户级最小修订事件刷新邮件列表、当前阅读详情和 Composer 联系人查询，不推送整份联系人或邮件正文。
- 邮件列表发件人优先显示解析后的联系人姓名；联系人不存在时保持邮件头姓名和邮箱降级，不改变分页、搜索或逐封到达性能。

### 统一联系人展示组件

- 建立共享联系人 Tag 组件，覆盖邮件列表发件人、邮件详情的发件人/收件人/抄送/密送等地址，以及 Composer 的 To/Cc/Bcc 标签和联系人建议。
- 指针稳定悬浮短暂延迟后或键盘聚焦时显示轻量名片，避免掠过地址时频繁闪现；名片至少包含解析后的姓名和完整邮箱，有本地联系人时可以进入联系人详情。
- 右键菜单提供“复制姓名”“复制邮箱地址”“复制姓名和邮箱”；没有独立姓名时禁用对应项，组合格式为 `姓名 <邮箱>`。
- Hover 不是唯一入口：键盘焦点可以获得同等信息，菜单具有可访问名称、焦点顺序和 Escape 关闭行为。
- 复制优先使用两端平台稳定的最小剪贴板能力；若 WebView Clipboard API 经实机不能满足，再经过许可、依赖与 Capability 审核增加官方 Tauri 剪贴板插件，只授权 main/composer 必需动作。

### Composer 联系人体验

- Composer 收件人标签复用同一联系人组件；输入时从当前账户联系人按姓名/邮箱给出建议，选择后写入规范的 `MessageAddress`，仍允许手工输入任意合法邮箱。
- 回复、回复全部、转发和草稿恢复执行相同解析与去重规则，但不静默改变实际收件邮箱。
- 从联系人详情点击“发送邮件”只使用当前账户打开 Composer 并预填该联系人，不影响其他已打开草稿。
- “设置 → 更多”增加联系人列表自动加载更多开关；开启时联系人列表接近底部自动取下一页，关闭时保留显式“加载更多联系人”按钮。
- 联系人身份右键菜单在当前窗口具备编辑上下文时提供“编辑联系人”，复用既有联系人编辑与冲突检查，不另建修改路径。
- 邮件模板定义保存 To、Cc、Bcc 和邮件标题；套用模板时只覆盖具有数据的字段，空字段保留草稿原值，地址仍使用既有解析与校验边界。账户范围模板复用自身账户联系人建议；全局模板编辑时只使用最近选中的单一账户作为候选来源，不合并或共享跨账户联系人。

- 增加联系人 Repository、薄 Command、账户级变化事件和集中 Query key，提供分页/搜索、建议、详情、最近往来、手动新增、姓名修改和批量地址解析；邮箱创建后只读。

- 邮件列表、邮件详情、联系人工作区和 Composer 收件人标签/建议统一使用本地联系人姓名优先；邮件详情发件人使用纯文本姓名加独立邮箱 Tag，其他交互身份使用 Tag 视觉。共享身份组件在短暂 hover 延迟或键盘聚焦后展示名片，支持右键复制姓名/邮箱/完整地址，并在主窗口允许跳转到联系人详情。

## 自动验证门禁

- 邮箱规范化、前缀命名、无效地址、重复地址、全部可观察地址字段、同邮箱跨账户隔离和手动名称不被同步覆盖。
- 同一邮件重复收取、头部更新、不同文件夹重复位置和历史回填不会产生重复联系人或关系；回填可中断、恢复和重复执行。
- 所有联系人 CRUD、最近往来、消息定位和公开联系人 ID 都复验账户归属，跨账户访问返回 `not_found`。
- 联系人入口不是 mailbox；工作区/账户切换、分页、搜索、稳定排序、编辑冲突、空状态和后台回填状态正确。
- 姓名优先级、无联系人降级、联系人改名刷新正确；邮件列表使用批量解析，没有逐行 Command 或 N+1 SQL。
- 邮件详情和 Composer 每个地址均能通过指针及键盘打开名片，右键复制三种格式；联系人建议严格限制当前账户。
- 本地联系人右键编辑复用既有账户隔离、revision 冲突和姓名验证；模板 To/Cc/Bcc 持久化、地址验证、邮件标题、账户联系人建议、手动套用和默认规则套用保持一致，并逐字段验证“有值覆盖、空值保留草稿”。
- 大数据量下分页、搜索、最近往来、邮件增量到达和回填保持有界，无无界 DOM、事件风暴或明显主壳重渲染。
- 执行 `pnpm test`、`pnpm build`、Rust fmt/test/clippy 与 `git diff --check`；不运行 Tauri bundle。

## 手动验收门禁

1. 使用真实旧数据目录升级，主窗口先正常可用；联系人后台逐步回填，中断重启后继续，重复同步不增加重复项。
2. 在 Inbox、Sent 和其他文件夹收取包含多种地址头的邮件，确认有效邮箱自动创建时优先采用有效邮件头显示名、无显示名时回退邮箱前缀；后续同邮箱的不同邮件头姓名不会改写已有联系人。
3. 在两个账户分别新增、修改和自动发现同一邮箱，确认列表、详情、姓名解析、最近往来和建议完全独立。
4. 在展开/折叠侧栏进入联系人，检查列表、搜索、详情、编辑、最近往来、邮件定位和写信预填。
5. 在邮件列表、阅读器发件人/多个收件人与 Composer To/Cc/Bcc 上验证姓名优先、hover、键盘名片和右键复制。
6. 使用大量联系人和邮件并行执行同步、搜索、阅读、回填和联系人改名，确认无明显卡顿、锁等待或陈旧显示。
7. 仅用键盘完成联系人主流程，并检查中英文、浅色/深色、主题色、长文本、缩放和窄窗口。
8. 分别检查 Windows 与实际可用的 macOS 环境；全部确认后由用户一次性验收第二十五阶段。
9. 新建和编辑全局/账户模板的 To/Cc/Bcc、邮件标题与正文，确认所有邮件内容字段都可留空；账户模板可使用当前账户联系人建议，全局模板不会读取账户联系人。
10. 分别通过 Composer 手动选择和四场景默认规则套用模板，确认 To、Cc、Bcc、邮件标题与正文只在模板有数据时覆盖，模板空字段保留草稿原值；升级前旧模板也不会清空现有内容。
