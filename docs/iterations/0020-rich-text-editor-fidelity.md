# 第二十阶段：富文本编辑器修正与保真

## 状态

已验收（2026-07-28）。

## 目标

围绕 Composer、签名和模板共用的 Tiptap/ProseMirror 编辑器修复可编辑性缺陷，明确 HTML 源码与结构化 WYSIWYG 的职责，减少不必要的样式偏差，并补齐邮件撰写所需的链接操作。

## 已确认范围

### 签名与模板编辑器

- 将第十九阶段验收后发现的签名/模板正文无法编辑问题纳入本阶段。
- 编辑器边框容器提供有界 flex 高度，使绝对定位的自绘滚动视口获得真实点击、输入和滚动区域。
- Composer 的现有工作区高度与滚动规则不改变。

### HTML 往返语义

- Tiptap 使用严格 ProseMirror schema，不宣称 WYSIWYG 可以无损编辑任意 HTML。
- `DraftContent.html` 作为 HTML 源码模式的权威文本传入共用编辑器；只打开、编辑并保存源码时，不使用 `editor.getHTML()` 覆盖用户源码。
- 从源码切换到 WYSIWYG 只建立可编辑投影，不立即改写持久化 HTML；用户随后实际进行 WYSIWYG 修改时，才按受支持 schema 重新序列化。
- 对 schema 无法表达的根级裸文本、未知标签或无效嵌套，不通过新增任意 DOM 节点或跳过 Rust 清洗来伪装“无损”。

### 邮件样式与图片尺寸

- 保留现有安全 HTML 中段落、标题、列表、引用、表格、`div`、`span`、链接与图片的 class、ID、方向、对齐及行内 style。
- 支持不含块级子节点的 `div` 作为内联内容容器，避免在其内部无理由插入 `<p>`。
- 编辑画布不再用 `max-width: 100%` 和 `height: auto` 覆盖图片的 `width`、`height` 与行内尺寸样式；超宽内容使用既有横向滚动，不改写邮件数据。
- 减少只为编辑器视觉添加、但不会进入最终 HTML 的元素级装饰；保留必要的画布留白、选区和结构边界。
- 本阶段不新增图片上传路径、拖拽缩放依赖或任意远程图片下载能力。

### 链接工具

- 在共用工具栏增加链接入口，支持为选区设置/更新链接、在空选区插入以 URL 为文本的链接，以及移除当前链接。
- 使用自有表单组件和中英文文案，不使用浏览器原生 `prompt`。
- 前端只接受显式 `http`、`https`、`mailto`，拒绝凭据、控制字符、反斜线和无效目标；保存时仍由 Rust Composer 清洗再次验证。
- 编辑器内链接不直接打开，最终邮件继续使用既有 `_blank`、`noopener noreferrer` 和 Rust 外链边界。

### 独立编辑窗口与插图

- 设置页中的签名/模板新增和编辑改为独立窗口，提供足够宽度容纳完整工具栏；Composer 已经是独立窗口，不改变其窗口生命周期。
- 独立窗口沿用平台标题栏、内容就绪后显示、首次居中与后续大小/位置记忆；相同范围和定义重复打开时聚焦既有窗口。
- 动态 `definition-*` 窗口使用单独的最小 Tauri capability，仅授权事件桥接和既有窗口控制；窗口不会因缺少 `event.listen` / `window.show` 权限而停留在隐藏状态。
- 设置窗口不持有独立编辑器的未保存状态；定义保存后由 Rust 发布只含账户公开 ID 和类型的最小事件，使对应 TanStack Query 失效。
- Composer 插图继续进入草稿附件缓存并使用 CID。签名/模板没有草稿附件归属，插入的本地 PNG/JPEG/GIF/WebP 由 Rust 验证文件魔数和 3 MiB 单图上限后，以受限 data URL 持久化到定义 HTML/JSON；不创建临时 CID、远程下载或新的文件存储。

## 非目标

- 不把 Tiptap 替换成任意 HTML/DOM 编辑器。
- 不允许脚本、表单、iframe、SVG、任意 data URL、任意文件路径或额外网络权限。
- 不新增组件库、商业编辑器、Cloud/Pro 功能或新的 Node/Rust 依赖。
- 不改变模板变量、默认签名、草稿、发件队列或 MIME 架构。

## 实施顺序

1. 修复签名/模板编辑器高度传递并补布局回归。
2. 让 HTML 源码作为显式输入传入编辑器，收敛源码/WYSIWYG 切换与保存语义。
3. 扩充受支持邮件节点和图片尺寸呈现，减少编辑器自定义视觉覆盖。
4. 增加安全链接表单、设置/更新/移除命令及中英文文案。
5. 补 HTML 往返、样式、图片和链接回归，更新长期项目手册和本阶段变更摘要。

## 手动验收

1. 在设置 → 写信中分别新建和编辑一个长签名、一个长模板，确认打开独立富文本窗口；首次窗口居中，调整大小/位置后重开可以恢复，正文可输入、滚动、保存并由设置列表自动刷新。
2. 在签名或模板 HTML 源码中输入不带段落包装的文本和带行内样式的 `div`/`span`；切换到预览、再切回源码并保存，确认源码没有被自动改成 `<p>...</p>`。
3. 在签名和模板中各插入一张不超过 3 MiB 的 PNG/JPEG/GIF/WebP，确认立即显示、保存重开仍存在；尝试超限文件或伪装扩展名，确认出现明确错误。再在 HTML 源码为图片设置 `width`、`height` 和行内尺寸/对齐样式，切回可视化编辑后确认显示一致。
4. 选中文字并使用链接按钮设置 `https` 或 `mailto` 地址，随后更新和移除；在空选区设置链接时确认以规范化地址作为链接文本插入。
5. 输入 `javascript:`、本机文件路径或带用户名密码的 URL，确认出现生产级错误文案且不会插入链接；切换中文和英文确认文案均完整。
6. 实机确认普通撰写、回复/转发、模板和默认签名应用仍正常，引用原文与附件行为不变。
