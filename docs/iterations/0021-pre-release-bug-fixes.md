# 第二十一阶段：首次测试版本发布前缺陷修正

## 状态

已验收（2026-08-01，用户确认）。

## 目标

在不改变既有邮件安全隔离、持久化发件和窗口 Capability 边界的前提下，修复首次测试版本发布前已经确认的内联 BMP、草稿生命周期、原生窗口标题、Composer 布局和邮件阅读入口问题，并补齐外观选择、动作邮件结构、账户全文同步策略和客户端邮件头标识。

## 已确认范围

### BMP 内联图片

- 已收邮件中被 HTML `cid:` 实际引用、但 MIME 类型误标为 `application/octet-stream` 的 BMP part，可在文件魔数确认后以内存 `data:image/bmp` URL 阅读。
- 邮件自带的 `data:image/bmp` 继续经过 media type、编码、文件魔数、单项 25 MB 与单封累计 100 MB 门禁。
- 未引用、格式伪装、损坏或超限的 part 仍作为附件，不因扩充格式而放宽 SVG、任意 data URL、文件或网络权限。
- 新增迁移只失效既有安全 HTML 缓存，使本地原始 EML 按新规则重建；不修改已发布迁移。

### 草稿生命周期

- 移除 Composer 停止输入后的自动保存和 10 秒后的自动 Drafts APPEND。
- 关闭可编辑 Composer 时显示自有确认界面，由用户选择取消关闭、不保存或保存为草稿。
- 选择保存后才持久化当前收件人、主题和三格式正文，并排入既有可靠 Drafts APPEND；失败时保留窗口并显示稳定错误。
- 选择不保存时删除当前本地编辑会话；远端导入草稿的服务器原件不受影响。
- 发送仍会先持久化当前内容并进入既有不可变 MIME 发件队列，不受关闭确认影响。
- 主侧栏移除“新建邮件”右侧的本地草稿下拉入口；用户保存的草稿以映射的 Drafts 文件夹为产品入口。
- Drafts APPEND 在服务器确认成功并完成待办后，只同步映射的 Drafts 文件夹并沿用既有逐封/文件夹事件刷新本地视图，不等待下一次完整账户同步；定向刷新失败不会重试已经成功的 APPEND，后续常规同步仍可恢复视图。
- Drafts 文件夹中的邮件只提供继续编辑及通用邮件操作，不提供回复、回复全部和转发。

### Composer 预览防御

- Rust 继续是模板、签名、草稿和发件 HTML 的权威清洗边界。
- Composer 为历史编辑内容重建 `about:srcdoc` 预览前，再移除脚本、iframe、表单等主动元素及 `on*` 事件属性，避免切换签名/模板时反复触发 sandbox 拦截日志；iframe 仍保持空 sandbox。
- 原始邮件 NodeView 只在 `sourceHtml`、纯文本回退或 CID 本地预览实际变化时重建 `srcdoc`；签名和模板的无关事务不再重新装载原文 iframe，也不会重新触发历史邮件主动内容的浏览器执行尝试。

### 邮件列表与独立预览

- 切换账户或文件夹时重新挂载邮件列表滚动视口，滚动位置回到顶部；分页缓存和 TanStack Query 数据事实不受影响。
- 双击邮件行或选择右键菜单/阅读器菜单中的“在新窗口中打开”，由 Rust 核验账户、文件夹和邮件归属后创建独立预览窗口。
- 独立预览复用既有 `MessageViewer`、安全正文、附件和邮件操作；打开时按既有待办语义标记已读，删除、移动或归档当前邮件后关闭窗口。
- 动态预览窗口使用独立 Capability、统一窗口状态类别和本地化标题；没有任意建窗、文件、网络、Shell 或数据库权限，邮件外链继续由宿主复验并交给系统浏览器。

### 窗口标题与 Composer 布局

- 设置、账户管理、邮件原文、模板/签名编辑器和 Composer 的原生窗口标题随当前中文/英文偏好创建，并在语言切换后更新已经打开的窗口。
- 品牌名和瞬时通知窗口标题保持 `NextMail`。
- Composer 发件人、收件人、抄送、密送与主题各行使用一致的单条分隔线。
- 抄送/密送展开按钮与收件人行垂直对齐。
- 移除 Composer 右上角“草稿已保存/正在保存”状态文字。

### 外观与账户管理

- 每个 WebView 的根级 Appearance Bridge 首次读取已保存外观；账户管理窗口等待该读取后显示，新增账户主操作显式使用全局主题色令牌，不依赖默认加载色或调用位置的隐式样式。
- 设置中的主题选择由下拉框改为“跟随系统 / 浅色 / 深色”三张可视化预览卡，继续使用同一外观 Query 和持久化 DTO；主题色选择保持不变。

### 回复、回复全部与转发结构

- 动作邮件标题按当前界面语言增加 `回复：` / `转发：` 或 `Re: ` / `Fwd: `；已经带有对应中文或标准英文前缀时不重复添加，场景模板主题也必须经过同一最终前缀规则。
- 回复与转发统一采用“回复正文、签名分隔线、签名、空行、原始邮件分隔线、原始邮件元数据、完整原文”的结构。
- 原始邮件元数据包含发件人、发件时间、收件人和主题；原始 HTML 仍作为不可跨越的原子节点，在空 sandbox iframe 中完整预览。
- 原始邮件元数据使用比正文小一档的 `13px` 字号，不改变邮件原文自身样式。
- 签名分隔线使用稳定 `nextmailSignatureDivider` / `data-nextmail-signature-divider` 语义节点；切换或移除签名时直接使用 ProseMirror 文档报告的真实节点区间，不再自行估算原子节点大小，因此不会越界删除原文，也不会遗留分隔线或给签名本身附加引用样式。

### 可选全文同步与邮件头标识

- 账户管理新增默认关闭的“收取邮件全文”选项，并明确说明存储空间和未下载正文不可搜索的取舍；迁移 0024 使用新的账户设置列，不复用阶段十二已废弃的兼容列。
- 开启后，完整账户同步在每个文件夹逐封落库邮件头后查询本地正文缺失位置，再通过同一批两条同步会话逐封获取完整 MIME；第三条账户会话容量继续保留给交互请求。
- 网络读取与 MIME 解析期间不持有 SQLite 写锁，正文回填不形成新邮件通知；单文件夹 Drafts 定向刷新不触发历史全文补齐。
- 新生成的发件和草稿 MIME 增加 `X-Mailer: NextMail/0.1.0`，不包含设备、账户或环境信息。

## 非目标

- 不新增邮件格式、账户协议、会话聚合或发布流水线。
- 不放宽 HTML iframe 的 sandbox/CSP、远程图片默认阻止或系统外链策略。
- 不引入新的编辑器、图片解码器、组件库或商业依赖。
- 不为草稿增加新的本地侧栏入口，也不改变 SMTP 发件和 IMAP Drafts 替换协议。

## 手动验收

1. 打开一封正文引用 `application/octet-stream` BMP CID part 的邮件，确认图片显示且不重复列为附件；伪装 BMP 仍显示为附件。
2. 新建、回复、转发和打开服务器草稿，分别验证关闭时的取消、不保存、保存三种动作；未确认保存的内容不进入草稿箱，确认保存的内容由 Drafts 文件夹打开。
3. 验证保存失败或 Drafts 映射不可用时窗口不会关闭，错误文案完整；发送流程仍正常。
4. 切换中文/英文后打开并观察主窗口、Composer、设置、账户管理、邮件原文及模板/签名编辑窗口的系统标题。
5. 检查 Composer 各地址行与主题行分隔线粗细一致，抄送/密送按钮垂直居中，右上角不再显示草稿保存状态。
6. 在签名之间反复切换，确认内容正确替换且开发日志不再出现 `about:srcdoc` 脚本执行拦截；脚本/iframe 等主动内容仍不能运行。
7. 保存草稿后进入 Drafts，确认服务器 APPEND 完成后列表立即出现草稿，无需手动或等待定时完整同步；断网保存失败时窗口仍保留。
8. 在 Drafts 文件夹的列表右键菜单和阅读器工具栏确认没有回复、回复全部、转发，仍可继续编辑、移动、删除等。
9. 将一个文件夹滚动到中部后切换另一文件夹，确认新文件夹从顶部显示；切回时同样从顶部开始。
10. 双击邮件以及使用右键菜单、阅读器“在新窗口中打开”，确认独立窗口正确显示、邮件标记已读、外链走系统浏览器，移动/归档/删除后窗口关闭。
11. 在外观设置切换三张主题预览卡，并改变主题色；确认新增账户按钮随主题色变化。
12. 分别新建中文/英文回复、回复全部和转发，确认主题前缀不重复，正文、分隔线、签名、空行、原始邮件分隔线与元数据顺序正确；切换/移除签名后分隔线同步变化。
13. 在一个账户开启“收取邮件全文”，同步包含尚未下载正文的文件夹；确认邮件头仍逐封出现，之后正文进度逐封推进，期间打开另一封缺失正文的邮件不会打断同步。关闭选项后，新邮件只收取头部并在打开时按需下载。
14. 发送一封邮件并查看原始邮件，确认存在 `X-Mailer: NextMail/0.1.0`，且不含设备或账户私有信息。
