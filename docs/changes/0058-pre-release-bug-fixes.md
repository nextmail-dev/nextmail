# 变更 0058：首次测试版本发布前缺陷修正

日期：2026-08-01

## BMP 内联图片

- 已收邮件的 CID 与 `data:image` 安全格式集合增加 BMP；误标为 `application/octet-stream` 的 part 只有在完整 BMP 文件头、文件大小、像素偏移和 DIB 长度均有界时才识别为 `image/bmp`。
- 简单伪造 `BM` 前缀、未引用、损坏、超限或不支持的 part 不会内联，仍保留为附件。
- Composer 的选择/粘贴图片和回复/转发 CID 导入同步接受经过相同文件魔数校验的 BMP，不新增图片解码依赖。
- 迁移 0023 将数据格式升级到 23，仅失效既有安全 HTML 缓存，使账户隔离的本地原始 EML 按新规则重建正文和附件投影。

## 显式草稿生命周期

- 移除 Composer 停止输入 800ms 后的自动保存，以及保存后 10 秒自动排入远端 Drafts 的逻辑。
- 关闭可编辑 Composer 时使用 NextMail 自有 Modal 提供取消、不保存和保存为草稿；关闭监听仍只注册一次，并通过 ref 读取最新内容。
- “保存为草稿”先持久化最新收件人、主题和三格式正文，再生成不可变 MIME 并排入既有 Drafts APPEND 待办；Drafts 映射缺失或任一步失败时窗口保持打开并显示稳定错误。
- “不保存”通过新增窄 Command 删除账户槽校验后的当前本地编辑会话；远端导入草稿的服务器原件不受影响。
- 主侧栏移除“新建邮件”右侧的本地草稿下拉入口，草稿统一从映射的 Drafts 文件夹进入；发送仍沿用持久化 MIME 与后台 SMTP 队列。
- Drafts APPEND 被服务器确认并持久完成后，只租用现有 IMAP 会话预算同步映射的 Drafts 文件夹；既有 `message-arrived`/`mailbox-changed` 事件让草稿立即进入本地列表，不启动完整账户同步，也不重复执行已经成功的 APPEND。
- Drafts 文件夹中的邮件隐藏回复、回复全部和转发，保留继续编辑和通用邮件操作。

## Composer 预览防御

- Rust 仍执行权威 HTML 清洗；前端在为历史模板/签名内容构造空 sandbox `srcdoc` 前，额外移除主动元素和 `on*` 事件属性。
- 原始邮件 NodeView 会记住已经渲染的 HTML、纯文本回退与 CID 预览映射；切换签名或模板产生的无关编辑事务不再重设 iframe `srcdoc`，因此不会重复让历史邮件中的主动内容触发 WebView sandbox 拦截日志。
- 初次构造预览仍会先删除主动内容，iframe 也继续使用空 sandbox；没有增加任何 sandbox allow token。

## 窗口标题与 Composer 视觉

- 集中 Rust 原生窗口标题映射，设置、账户管理、邮件原文、模板/签名编辑器和 Composer 创建时使用当前中文/英文偏好；语言变化会更新已经打开的窗口标题。
- Windows 自绘标题栏中的 Composer、设置、账户管理、原始邮件与定义编辑标题继续由同一 i18n 事实渲染。
- Composer 地址与主题行改用完整宽度、相同粗细的单条分隔线；抄送/密送按钮与收件人行垂直对齐。
- 移除右上角“草稿已保存/正在保存”状态，保存状态只在明确关闭动作或发件流程中体现。

## 邮件列表与独立预览

- 邮件列表滚动视口以账户和文件夹为身份重新挂载，切换文件夹后总是从顶部开始，不沿用上一个文件夹的滚动位置。
- 邮件行双击、列表右键菜单和阅读器更多菜单都可请求“在新窗口中打开”；命令先核验公开账户、文件夹和邮件归属，再创建按邮件 ID 复用的动态预览窗口。
- 预览窗口复用现有 `MessageViewer` 和安全正文管线，打开时沿用可靠待办标记已读，移动/归档/删除当前邮件后销毁窗口。
- 新增 `message-preview-*` 独立 Capability 和统一 `message-preview` 窗口状态类别。窗口没有文件、网络、Shell、数据库或任意建窗能力；外部链接继续由 Rust 宿主复验后交给系统关联程序。

## 外观与账户全文同步

- 每个 WebView 的根级 Appearance Bridge 都会读取已保存外观，账户管理窗口等待该首次读取后才显示；新增账户按钮显式使用主题色主按钮。外观主题由下拉框改为跟随系统、浅色、深色三张可访问的可视化预览卡，继续写入既有外观偏好单一事实。
- 迁移 0024 为 `account_sync_settings` 增加默认关闭的 `download_full_messages`，数据格式升级至 24；没有复用阶段十二已废弃的 `download_non_inbox_bodies`。
- 账户管理可独立开关“收取邮件全文”，并展示空间占用与未下载正文不可搜索的说明。
- 开启时，完整同步在逐封邮件头阶段后查询当前文件夹缺失正文，并用原有两条同步 worker 会话逐封 FETCH 完整 MIME；第 3 条账户会话继续保留给交互正文、附件或待办操作。网络/解析不持有数据库锁，正文 UPSERT 才短暂串行写入。
- Drafts APPEND 后的单文件夹定向刷新明确跳过全文补齐，避免一次保存草稿拉取整个历史草稿箱。

## 回复/转发组成与客户端标识

- 回复、回复全部和转发主题根据界面语言使用中文 `回复：` / `转发：` 或英文 `Re: ` / `Fwd: `，并在应用场景模板主题后再次执行相同的防重复前缀规则。
- 两类动作统一使用回复区、签名分隔线、签名、空行、原始邮件分隔线、发件人/发件时间/收件人/主题元数据和完整原始 HTML 的结构。
- 原始邮件元数据改用 `13px` 字号和紧凑行高，原始邮件正文自身样式不受影响。
- 新增稳定的签名分隔线编辑器节点；签名查找与替换直接使用 ProseMirror `nodeSize` 给出的真实区间，不再用 JSON 递归估算原子节点大小。切换或删除签名不会越过原文边界，也不会把分隔线变成签名自身样式。
- 发件与远端草稿 MIME 增加 `X-Mailer: NextMail/0.1.0`，仅暴露公开产品名和版本。

## 边界

- 邮件正文仍由 Rust 清洗并在原有 sandbox/CSP 中渲染；没有开放脚本、表单、same-origin、顶层导航、任意文件或网络权限。
- 没有新增 Node/Rust 依赖、Cargo package、前端持久化或本地草稿入口。
- 定向 Drafts 刷新只在 APPEND 已完成后运行，不持有 SQLite 写锁等待网络，也不改变启动、定时或手动完整同步入口。
