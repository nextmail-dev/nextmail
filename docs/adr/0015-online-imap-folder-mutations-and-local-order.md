# ADR 0015：在线 IMAP 文件夹结构操作与独立本地顺序

状态：已接受

日期：2026-07-27

## 背景

NextMail 已经为单封邮件的 Flags、移动、复制、删除和 Drafts/Sent APPEND 建立持久化待办队列。这些操作有稳定的 UID、UIDVALIDITY、源/目标 mailbox 和可回滚本地投影，可以在断网后重放。

文件夹创建、重命名、层级移动和删除的语义不同：路径本身就是服务器身份，`RENAME` 还会同时改变全部下级路径；离线排队期间其他客户端可能创建同名路径、删除父级或改变层级分隔符。若只乐观修改本地树，失败回滚需要保存完整子树和所有中间服务器状态，容易产生无法与下一次 LIST 对账的重复 mailbox。

另一方面，服务端 LIST 顺序不是稳定的用户偏好。用户只想调整 NextMail 本机的展示顺序时，不应发送 `RENAME` 或更改服务器层级。

## 决策

- 文件夹 CREATE、RENAME、层级移动和 DELETE 是显式在线操作，不加入现有消息待办队列，也不触发额外完整同步。
- MailRuntime 先按公开账户 ID 解析匿名数据槽并读取短生命周期 mailbox 上下文，然后释放数据库访问；具体 `AsyncImapProvider` 租用账户第三条交互会话执行协议命令，操作结束即 LOGOUT。
- Adapter 按账户维护弱引用的 mailbox 路径读写锁。完整同步、正文 FETCH、消息待办和 APPEND/草稿替换持共享读锁，彼此仍可并发；文件夹结构操作和全部已读持独占写锁，等待正在使用旧路径或旧 Flags 快照的操作完成后再连接服务器。锁只保护协议操作，不跨 SQLite 访问。
- 只有服务器返回成功后，独立 `MailboxRepository` 才在本地事务中创建、改名或删除投影。网络等待期间不持有 SQLite 事务或写锁。
- Unicode 叶名称在 IMAP Adapter 内编码为 modified UTF-7；React 只提交叶名称、mailbox ID 和目标父 mailbox ID，不接触线缆路径、分隔符或协议类型。
- `INBOX` 不允许重命名、移动或删除；移动不能选择自身或自身下级。`RENAME` 成功后，本地以稳定 mailbox ID 同时改写源节点和全部下级的远端/显示路径。
- 文件夹“全部标为已读”同样使用在线交互会话，以单次 `UID STORE 1:* +FLAGS.SILENT (\Seen)` 修改服务器；成功后事务更新本地位置 Flags 和文件夹未读数。
- 本地排序与服务器层级严格分离。`mailboxes.local_sort_order` 按匿名账户槽保存完整展示顺序；拖拽只允许同父级，并把父节点及其子树作为连续块移动。新发现文件夹追加在已显式排序项之后；从未排序的账户继续使用既有角色优先和名称顺序。

## 影响

- 文件夹结构变更在离线时会直接失败并返回可重试稳定错误，不会显示尚未被服务器接受的乐观树。
- 服务器成功而本地投影写入失败时，日志保留协议/存储原因；下一次正常 LIST 可重新发现服务器结构，但这是需要实机重点验证的罕见恢复路径。
- 本地排序不会影响 Web 邮箱或其他客户端；服务器层级移动必须使用右键菜单，长按拖拽不会意外发送 RENAME。
- 文件夹操作复用 ADR 0014 的账户级会话预算，不增加第四条连接，也不改变 ADR 0013 的启动/周期/手动完整同步入口；路径读写锁不会把正文、待办和同步重新串行化。
- 消息待办队列的离线可靠性不变；未来若要支持离线文件夹结构操作，必须单独设计路径版本、冲突与整树补偿语义。

## 验证门禁

- modified UTF-7 编解码与父/叶路径拼接有单元测试。
- 路径锁回归固定同账户共享读、结构写等待和不同账户互不阻塞。
- Repository 回归固定重命名保留 ID、下级路径同步改写、完整账户排序集合校验和账户隔离。
- 前端回归固定父节点携带完整子树排序、跨父级拒绝和右键菜单动作。
- 真实服务商验收 CREATE、RENAME、DELETE、批量 `\Seen`、非空/含下级删除拒绝，以及重启/完整同步后的本地顺序。
